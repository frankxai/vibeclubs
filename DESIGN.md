# Vibeclubs Design System

## Product role

Vibeclubs is an open focused-work ritual with an optional hosted upgrade for durable crews. The public site must make the full host → join → focus → ship → recap loop inspectable before it asks for an account.

## First read

Lock in together. Leave with proof.

The first viewport must establish that Vibeclubs works wherever a crew already meets, that the core format is open, and that a real local proof is available now.

## Visual system

- Foundation: ink `#0a0a0f`, elevated ink `#0d0d15`, white hairlines at 8–10% opacity.
- Signals: amber for the active ritual; green only for ready/live states; violet remains a depth accent.
- Type: large tight grotesk headlines, readable system sans body, mono only for sequence and runtime state.
- Material: one instrument-like proof surface; no nested dashboard theater.
- Primary asset: Tier C exact product UI backed by the real timer and card packages.

## Motion

Named behavior: `proof-breathe`. A low-amplitude background glow gives the first viewport depth without moving content. The real countdown is functional state, not decoration. All decorative motion stops under `prefers-reduced-motion: reduce`.

## Stop conditions

- Static numbers, fake attendees, or sample cards presented as live proof.
- AI described as watching, listening, or reading content it does not receive.
- Paid capabilities shown as available before they can be verified.
- A public form without a real persistence and consent path.
- Decorative 3D, node/orbit motifs, or generated media used instead of product truth.
